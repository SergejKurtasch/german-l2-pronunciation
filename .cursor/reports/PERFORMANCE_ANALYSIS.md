- **Запуск 2**: 5.8 секунд

### Основные узкие места:

#### 1. G2P Dictionary Loading: **31.4 секунды** (среднее)
- **Проблема**: Словари загружаются лениво при первом использовании
- **Решение**: ✅ Добавлена предзагрузка в `initialize_components()`
- **Ожидаемый эффект**: Словари загрузятся один раз при старте, не блокируя обработку

#### 2. G2P Processing: **14.5 секунд** (среднее, до 29 сек)
- **Проблема**: Медленная обработка текста в фонемы
- **Решение**: ✅ Добавлено кэширование результатов G2P (до 1000 записей)
- **Ожидаемый эффект**: Повторные запросы с тем же текстом будут мгновенными

#### 3. ASR (Whisper): **6.1 секунды** (среднее)
- **Проблема**: ASR запускается даже когда текст уже предоставлен
- **Решение**: ✅ Добавлена настройка `ASR_ALWAYS_RUN = False` в config.py
- **Ожидаемый эффект**: Экономия ~6-7 секунд когда текст уже есть

#### 4. Инициализация компонентов: **5.2 секунды**
- Phoneme recognizer: 5.2 сек
- **Статус**: Уже оптимизировано (загружается один раз)

#### 5. Phoneme Recognition: **1.5 секунды**
- Model inference: 172ms
- Audio loading: 410ms
- **Статус**: Приемлемо, дальнейшая оптимизация не критична

## Внедренные оптимизации

### ✅ 1. Предзагрузка G2P словарей
**Файл**: `app.py`, функция `initialize_components()`

Словари теперь загружаются сразу при инициализации компонентов, а не при первом использовании. Это экономит ~31 секунду при первом запуске.

### ✅ 2. Кэширование G2P результатов
**Файл**: `modules/g2p_module.py`, функция `get_expected_phonemes()`

Добавлен кэш на 1000 записей для результатов G2P. Повторные запросы с тем же текстом выполняются мгновенно.

### ✅ 3. Опциональный ASR
**Файл**: `config.py`, `app.py`

Добавлена настройка `ASR_ALWAYS_RUN = False`. Когда текст уже предоставлен пользователем, ASR не запускается, экономя ~6-7 секунд.

## Дополнительные рекомендации (если нужно еще ускорить)

### 1. Использовать только DSL словарь (если доступен)
Если DSL словарь загружен успешно, можно пропустить MFA и eSpeak для экономии времени. Это может сэкономить еще ~5-10 секунд на G2P обработке.

### 2. Параллельная обработка
- Загружать waveform для forced alignment параллельно с phoneme recognition
- Выполнять визуализацию параллельно с другими операциями

### 3. Оптимизация модели
- Использовать более легкую модель Whisper (tiny/base вместо medium) если точность ASR не критична
- Использовать quantization для модели phoneme recognition

### 4. Предзагрузка всех компонентов
Убедиться, что все компоненты загружаются при старте приложения, а не при первом использовании.

## Как проверить улучшения

1. Перезапустите приложение
2. Выполните два теста:
   - Первый запуск после перезапуска
   - Второй запуск (должен использовать кэш)
3. Проверьте логи в `.cursor/debug.log`:
   - `g2p_module.py:_load_dictionaries:end` - должно быть только при старте
   - `app.py:process_pronunciation:after_g2p` - должно быть <2 сек после первого запуска
   - `app.py:process_pronunciation:after_asr_optional` - не должно быть если `ASR_ALWAYS_RUN = False` и текст предоставлен

## Настройки конфигурации

В `config.py` добавлена новая настройка:
```python
ASR_ALWAYS_RUN = False  # Если False, пропускает ASR когда текст уже есть
```

Установите `ASR_ALWAYS_RUN = True` если нужен ASR даже когда текст предоставлен.
