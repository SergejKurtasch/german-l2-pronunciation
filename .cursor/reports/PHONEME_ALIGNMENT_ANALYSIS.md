## 🔴 **Критическая проблема #1: Разделители слов `||`**

### Описание проблемы
В результатах alignment наблюдается **массовое количество ошибок `-||`** (deletions разделителей слов).

**Причина:**
- **Expected phonemes** (из G2P/текста): содержат маркеры границ слов `||`
  ```python
  ['aɪ', 'n', 'ə', '||', 'f', 'ʊ', 'ŋ', 'k', ...]
  ```
- **Recognized phonemes** (из Wav2Vec2/аудио): НЕ содержат границ слов
  ```python
  ['aɪ', 'n', 'ə', 'f', 'ʊ', 'ŋ', 'k', ...]
  ```

**Модель Wav2Vec2 не обучена предсказывать границы слов** - она выдает непрерывный поток фонем.

### ✅ Решение (УЛУЧШЕННАЯ РЕАЛИЗАЦИЯ)
**ВСТАВЛЯТЬ `||` в recognized phonemes** на основе **ТЕКСТА** и структуры expected phonemes.

Используется **word-based пропорциональное распределение** (улучшенная версия):

**Алгоритм:**
1. **Разбиваем ТЕКСТ на слова**: `text.split()` → `['an', 'Nadine']`
2. **Разбиваем expected phonemes по `||`** на группы (слова):
   ```python
   ['a', 'n', '||', 'n', 'a', 'd', 'i', 'n', 'ə']
   → [['a', 'n'], ['n', 'a', 'd', 'i', 'n', 'ə']]
   ```
3. **Пропорционально распределяем recognized phonemes** по словам:
   - Слово 1: 2 фонемы из 8 total → 2/8 * 8 recognized = 2 фонемы
   - Слово 2: 6 фонем из 8 total → остальные фонемы
4. **Вставляем `||` между группами**:
   ```python
   ['a', 'n', '||', 'n', 'a', 'd', 'i', 'n', 'ə']
   ```

**КРИТИЧЕСКИ ВАЖНО:** 🎯 **Сохраняются все фонемы**, даже если они одинаковые на границах слов!

**Пример с одинаковыми фонемами на границе:**
```python
text: "an Nadine"

Expected:   ['a', 'n', '||', 'n', 'a', 'd', 'i', 'n', 'ə']
            #     ^^^^ слово 1     ^^^^ слово 2
            #        n (конец "an")  n (начало "Nadine")

Recognized: ['a', 'n', 'n', 'a', 'd', 'i', 'n', 'ə']  (без ||)
            #     первое n      второе n

Result:     ['a', 'n', '||', 'n', 'a', 'd', 'i', 'n', 'ə']
            #   ОБЕ фонемы 'n' сохранены и НЕ схлопнуты!
```

**Реализация:**
```python
# Файл: modules/word_boundary_utils.py
from modules.word_boundary_utils import insert_word_boundaries

# В функции extract_phonemes_for_record:
recognized_phonemes_with_boundaries = insert_word_boundaries(
    text,                    # ИСПОЛЬЗУЕМ ТЕКСТ для определения границ!
    expected_phonemes_raw,   # WITH ||
    recognized_phonemes_raw  # WITHOUT ||
)
```

**Преимущества новой реализации:**
- ✅ Использует **текст** для точного определения границ слов
- ✅ **НЕ теряет фонемы** на границах слов (важно для "an Nadine", "mit Tina", и т.д.)
- ✅ Более точное распределение по словам (не просто пропорция, а word-aware)
- ✅ Fallback на старый алгоритм, если количество слов не совпадает

**Результат:** Обе последовательности имеют `||`, alignment корректен, можно анализировать ошибки с учетом границ слов.

## 🟡 **Проблема #2: Аффрикаты (ts, pf, tʃ, dʒ)**

### Описание проблемы
Несогласованность в представлении аффрикат между словарем и моделью:

| Источник | Пример 1 | Пример 2 | Пример 3 |
|----------|----------|----------|----------|
| **DSL словарь** | `s t` (2 phoneme) | `p f` | `t ʃ` |
| **Модель** | `ʃ t` или `ts` | `pf` | `tʃ` |

**Примеры из данных:**
```
Слово: "Station"
Expected:  s t ɑ t s oː n  (s и t отдельно)
Recognized: ʃ t a ts oː n   (ts как одна аффриката)
→ Создает 3 ошибки: s→ʃ, t→t (match), -s, +ts
```

```
Слово: "Pferd" (лошадь)
Expected:  p f eː ɐ t
Recognized: pf eː ɐ t
→ Создает 2 ошибки: -p, -f, +pf
```

### Влияние на метрики
- **2-3 ложных ошибки на каждую аффрикату**
- Особенно критично для немецких слов с `pf`, `ts`, `tʃ`
- Добавляет **5-10% к общему PER**

### ✅ Решение (ВНЕДРЕНО)
Нормализация аффрикат - приведение к единому формату (всегда split):

```python
def normalize_affricates(phonemes, split_mode=True):
    """
    Разбить аффрикаты на компоненты:
    'ts' -> ['t', 's']
    'tʃ' -> ['t', 'ʃ']
    'pf' -> ['p', 'f']
    'dʒ' -> ['d', 'ʒ']
    """
    affricate_map = {
        'ts': ['t', 's'],
        'tʃ': ['t', 'ʃ'],
        'dʒ': ['d', 'ʒ'],
        'pf': ['p', 'f'],
        'dz': ['d', 'z'],
    }
    result = []
    for ph in phonemes:
        if ph in affricate_map:
            result.extend(affricate_map[ph])
        else:
            result.append(ph)
    return result

# Применить к обеим последовательностям:
expected_phonemes = normalize_affricates(expected_phonemes)
recognized_phonemes = normalize_affricates(recognized_phonemes)
```

**Результат:** Устранение ~200-400 ложных ошибок, более честная оценка фонемных замен.

## 🟢 **Проблема #3: Aspirated consonants (придыхание)**

### Описание проблемы
Немецкие глухие взрывные `p, t, k` часто произносятся с **придыханием** `[pʰ], [tʰ], [kʰ]`:

**Примеры:**
```
"Tag" [tʰaːk] - t с придыханием
"Park" [pʰaʁk] - p с придыханием
"Kind" [kʰɪnt] - k с придыханием
```

**В словарях:**
- DSL может содержать: `tʰ` (один символ - t + combining modifier)
- MFA может содержать: `t` (без придыхания)

**Модель Wav2Vec2:**
- Обучена на транскрипциях **без разметки придыхания**
- Возвращает просто: `t`, `p`, `k`

### Влияние на метрики
- Средний уровень (1-3% PER)
- Больше касается **акустически точной транскрипции**, чем практического распознавания

### 🔧 Рекомендации
**РЕШЕНИЕ: Оставить как есть**

Придыхательные фонемы оставляем в текущем виде, так как:
1. Планируется **второй этап проверки** с другой моделью
2. Новая модель может иметь эти фонемы в словаре
3. На текущем этапе это позволит выявить проблемные места

Альтернативные варианты (если потребуется позже):

**A. Удалить придыхание из expected:**
```python
# Убрать диакритик ʰ из словарных фонем
expected_phonemes = [ph.replace('ʰ', '') for ph in expected_phonemes]
```

**B. Добавить в phoneme_normalization_table.json:**
```json
{
  "char": "ʰ",
  "unicode": "U+02B0",
  "in_dsl": true,
  "in_mfa": false,
  "reason": "Aspiration - model not trained to recognize it"
}
```

**C. Fine-tune модель** с датасетом, размеченным по придыханию (трудоемко).

## 🚀 **Дополнительные рекомендации**

### 1. **Unicode нормализация** (уже реализовано частично)
Убедиться, что все тексты в **NFC** (Canonical Decomposition, followed by Canonical Composition):
```python
import unicodedata
text = unicodedata.normalize('NFC', text)
```

### 2. **Длинные vs короткие гласные**
Проблема: `aː` vs `a`, `iː` vs `i`

**Текущее решение:** Модель различает длину  
**Альтернатива (если много ошибок):**
```python
# Убрать length marker ː
phonemes = [ph.replace('ː', '') for ph in phonemes]
```

### 3. **r-звуки (ʁ vs r vs ɾ)**
В немецком:
- `ʁ` - увулярный фрикативный (стандартное немецкое r)
- `r` - альвеолярный трель (раскатистое r)
- `ɾ` - альвеолярный flap (короткое r)

**Рекомендация:** Объединить все r-варианты в один (если модель путает):
```python
r_variants = {'ʁ': 'r', 'ɾ': 'r', 'ʀ': 'r'}
phonemes = [r_variants.get(ph, ph) for ph in phonemes]
```

### 4. **Дифтонги vs моно-гласные**
Проверить консистентность:
- `aɪ` (дифтонг "ai") vs `a ɪ` (два звука)
- `aʊ` (дифтонг "au") vs `a ʊ` (два звука)
- `ɔʏ` (дифтонг "oy") vs `ɔ ʏ` (два звука)

### 5. **Schwa (ə) vs другие гласные**
Модель часто путает:
- `ə` ↔ `ɐ` (центральные гласные)
- `ə` ↔ `e` (в безударных позициях)

**Решение:** Phoneme similarity matrix уже учитывает это (см. `modules/phoneme_similarity.py`).
